Alke Wallet — Base de Datos (SQL)

Diseño e implementación de un modelo de base de datos relacional en MySQL para Alke Wallet: normalización hasta 3FN, tablas con integridad referencial (claves primarias y foráneas), transacciones controladas con COMMIT y ROLLBACK para garantizar las propiedades ACID, y consultas SQL con INNER JOIN, filtros y funciones de agregación.

Caso de estudio

  • Desafío principal: diseñar un modelo que garantizara la integridad de los datos financieros, de forma que ninguna transferencia quedara "a medias" si algo fallaba a mitad de camino.
  • Solución propuesta: normalicé el modelo hasta 3FN, definí claves primarias y foráneas entre usuarios, monedas y transacciones, e implementé bloques de transacción con COMMIT y ROLLBACK para simular tanto un envío de dinero exitoso como uno que debía revertirse por un error de integridad.
  • Herramienta técnica utilizada: MySQL como motor de base de datos y DBeaver para diseñar, ejecutar y depurar las consultas SQL (DDL y DML).
  • Principales aprendizajes: a pensar en los datos en términos de relaciones antes de escribir una sola línea de SQL, y a entender en la práctica para qué sirven las transacciones — no es lo mismo leerlo en un apunte que ver cómo un ROLLBACK evita que quede un registro huérfano en la base de datos.
  • Métricas de impacto: 3 tablas relacionadas con integridad referencial, 2 transacciones controladas (COMMIT y ROLLBACK), y consultas con INNER JOIN y funciones de agregación sobre datos de prueba.
  • Habilidades técnicas aplicadas: modelado entidad-relación, normalización (3FN), SQL (DDL/DML), transacciones ACID, JOIN y funciones de agregación.
  • Por qué lo elegí para mi portafolio: es el proyecto donde más avancé de "saber que existen las bases de datos" a diseñar y proteger una con reglas de negocio reales (dinero, usuarios, transferencias) — el que mejor muestra cómo resuelvo un problema técnico de punta a punta.

  • Modelo Entidad-Relación
